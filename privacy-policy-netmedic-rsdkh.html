Kebijakan Privasi Netmedic RSDKH

Kebijakan ini menjelaskan bagaimana extension Netmedic RSDKH menangani data ketika membantu pengguna yang berwenang menyiapkan dokumentasi klinis pada sistem eRM RSDKH.

Berlaku sejak 28 Agustus 2026
Informasi penting: Netmedic RSDKH adalah alat bantu dokumentasi. Seluruh hasil AI, resep, SOAP, kronologi, dan data yang akan dimasukkan ke eRM wajib diperiksa dan disetujui oleh tenaga kesehatan yang berwenang.

1. Pengelola dan ruang lingkup

Netmedic RSDKH dikembangkan dan dikelola oleh Syafrie Yunizar (selanjutnya disebut "Pengembang"). Kebijakan ini berlaku untuk extension Chrome Netmedic RSDKH.

Tujuan tunggal extension adalah membantu pengguna RSDKH yang berwenang menyiapkan, meninjau, menyalin, dan memasukkan dokumentasi klinis ke eRM RSDKH. Fitur pendukung mencakup Magic SOAP, kronologi BPJS, pemetaan e-Resep, memori pasien dan sesi jaga lokal, format laporan WhatsApp, serta capture hasil laboratorium ke clipboard.

2. Data yang ditangani

Extension dapat menangani data berikut hanya sejauh diperlukan untuk menyediakan fitur yang dipilih pengguna:

Identitas pribadiNama pasien, jenis kelamin, umur, nomor rekam medis, nomor registrasi, identitas dokter, dan data identitas lain yang tampil atau dimasukkan pada eRM.
Informasi kesehatanKeluhan, riwayat penyakit, tanda vital, pemeriksaan fisik, diagnosis, rencana terapi, obat, hasil laboratorium, kronologi medis, serta foto klinis yang dipilih pengguna.
Informasi autentikasiUsername, password saat proses login, token sesi, pengenal perangkat, API key pribadi, nama model, dan alamat endpoint provider. Password login tidak disimpan secara persisten oleh extension; token sesi dan pengaturan API dapat disimpan secara lokal.
Konten situsKonten pada halaman eRM RSDKH yang diperlukan untuk mengambil identitas pasien, instruksi dokter, resep, status asesmen, dan hasil laboratorium, serta untuk memasukkan kembali dokumentasi yang telah ditinjau.
Data penggunaan khusus eRMURL eRM pasien, nomor BED, status pasien, waktu sesi jaga, dan riwayat pasien yang diperlukan untuk navigasi dashboard lokal. Extension tidak mengumpulkan riwayat penjelajahan umum di luar halaman yang didukung.

3. Cara data digunakan

  • Menyusun dan memformat SOAP, kronologi BPJS, e-Resep, dan laporan klinis.
  • Mengambil data yang relevan dari halaman eRM dan mengisi kembali kolom eRM setelah tindakan pengguna.
  • Menyimpan draft, riwayat, preferensi, status sesi jaga, dan memori pasien pada perangkat pengguna.
  • Menganalisis teks atau foto klinis dengan provider AI hanya ketika pengguna menjalankan fitur terkait.
  • Menyalin teks atau gambar hasil laboratorium ke clipboard ketika pengguna menekan tombol salin atau capture.
  • Memvalidasi sesi API admin dan menjaga keamanan akses pengguna.

Data tidak digunakan untuk iklan, profil pemasaran, pemeringkatan kredit, pemberian pinjaman, atau tujuan lain yang tidak berkaitan dengan fungsi extension.

4. Penyimpanan lokal dan retensi

Draft SOAP dan kronologi, hasil sebelumnya, memori pasien, daftar BED, sesi jaga, template WhatsApp, alias produk, pengaturan provider, API key pribadi, dan token sesi dapat disimpan menggunakan chrome.storage.local pada profil browser pengguna.

  • Riwayat pasien dan sesi jaga dibatasi hingga sekitar 60 hari dan dapat dihapus secara manual dari antarmuka extension.
  • Draft, preferensi, API key pribadi, dan data lokal lain disimpan sampai dihapus oleh pengguna, extension di-reset, atau extension dihapus.
  • Gambar capture hasil laboratorium tidak disimpan sebagai file oleh extension; gambar hanya ditempatkan pada clipboard atas tindakan pengguna.
  • Foto klinis disimpan sementara di memori untuk diproses dan tidak dimasukkan ke riwayat lokal oleh fitur foto klinis.

5. Pengiriman data dan pihak penerima

Fitur inti lokal tidak memerlukan pengiriman data kepada Pengembang. Ketika pengguna memilih fitur AI, prompt dapat memuat informasi identitas dan kesehatan yang dimasukkan atau diambil dari eRM. Data tersebut dikirim hanya untuk menghasilkan hasil yang diminta kepada salah satu pihak berikut:

  • Google Gemini API, jika Gemini dipilih sebagai provider.
  • Sumopod, AImurah, atau SemutSSH, jika salah satu provider kompatibel tersebut dipilih.
  • Provider HTTPS khusus pilihan pengguna, jika pengguna mengonfigurasi endpoint sendiri dan memberikan izin host.
  • Supabase pada proyek backend Netmedic RSDKH, untuk autentikasi API admin, konfigurasi, dan penerusan permintaan AI pada mode API admin.
  • Provider AI yang dikonfigurasi oleh administrator, ketika mode API admin digunakan.

Provider pihak ketiga dapat memproses data sesuai ketentuan dan kebijakan privasi mereka. Pengguna atau administrator bertanggung jawab memilih provider yang sesuai dengan kebijakan organisasi dan peraturan yang berlaku.

Interaksi dengan eRM dikirim ke sistem RSDKH yang sedang dibuka pengguna. Komunikasi internet menuju layanan AI dan Supabase menggunakan HTTPS. Endpoint eRM intranet dapat mengikuti konfigurasi jaringan internal rumah sakit.

7. Berbagi, penjualan, dan Limited Use

Pengembang tidak menjual data pengguna dan tidak mentransfer data kepada pihak ketiga kecuali sebagaimana diperlukan untuk menyediakan fitur yang dipilih pengguna, menjaga keamanan, memenuhi kewajiban hukum, atau setelah persetujuan eksplisit pengguna jika diwajibkan.

Pengembang tidak menggunakan atau mentransfer data untuk iklan yang dipersonalisasi, penargetan ulang, penilaian kredit, atau tujuan yang tidak berhubungan dengan tujuan tunggal extension. Pengembang tidak mengizinkan manusia membaca data klinis kecuali atas persetujuan pengguna untuk dukungan kasus tertentu, untuk keamanan, atau untuk memenuhi kewajiban hukum.

Penggunaan informasi yang diterima melalui Chrome dan API terkait akan mematuhi Chrome Web Store User Data Policy, termasuk persyaratan Limited Use.

8. Keamanan

Extension membatasi akses host sesuai layanan yang diperlukan, membundel seluruh kode yang dijalankan, tidak menjalankan kode JavaScript atau WebAssembly dari server jarak jauh, dan menggunakan HTTPS untuk layanan internet. API key pribadi disimpan pada profil browser lokal. Tidak ada metode penyimpanan atau transmisi yang dapat dijamin aman sepenuhnya; pengguna harus menjaga keamanan perangkat, akun, dan API key.

9. Pilihan dan penghapusan data

Pengguna dapat menghapus riwayat melalui antarmuka extension, menghapus API key pribadi melalui Pengaturan, logout dari API admin, atau menghapus seluruh data lokal dengan menghapus atau me-reset extension. Untuk permintaan terkait data backend atau akun API admin, hubungi Pengembang menggunakan alamat di bawah.

10. Perubahan kebijakan

Kebijakan ini dapat diperbarui ketika fitur, provider, atau praktik data berubah. Tanggal berlaku akan diperbarui pada halaman ini. Perubahan material pada praktik data akan diungkapkan melalui listing atau antarmuka extension sebagaimana diwajibkan.
